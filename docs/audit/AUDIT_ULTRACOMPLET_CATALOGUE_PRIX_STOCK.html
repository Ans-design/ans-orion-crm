Verdict Release Candidate : le code Vague 2 / hub Catalogue-Prix-Stock est largement avancé et testable en local. La production reste NO-GO faute de backup PostgreSQL restaurable, de sync multi-entités non atomique, et de décisions propriétaire ouvertes (payment drift, staging Hostinger, PDF V17).

1.1 Ce qui est solide

  • Hub canonique unique /administration/catalogue-prix-stock
  • Navigation 5 domaines + alias techniques (zéro suppression de routes)
  • getPosCatalogue() en lecture pure — maintenance explicite via sync
  • Fiche produit unifiée (liste dense, OptionsChips embarqué, garde dirty/beforeunload)
  • Matières unifiées (6 sous-vues) + lien stock
  • Consommation stock production centralisée + idempotence
  • Guards déploiement fail-closed (ALLOW_VERCEL_DB_PUSH_DATA_LOSS, ALLOW_PROD_DB_SETUP, ALLOW_NEON_DB_PUSH)

9. Services, sync & graphes d’appels

9.1 Route /pricing/sync-pos

1. requirePermission('config:publish')
2. runPosCatalogueMaintenance({ force: true })
3. Promise.all([
     syncBackofficeCatalog(),
     syncPricingMaterialsToPos({ publish: true, userId })
   ])
4. Retourne { catalog, materials, maintenance }
5. Exception → HTTP 500 SYNC_POS_ERROR

9.2 admin-to-commercial-sync.syncAll()

1. Options full / options / directSale / prices
2. full → runPosCatalogueMaintenance + syncCatalogueProfilesToDb
3. options → syncArticleOptionsToPOS + deps + merge formats (toléré)
4. directSale → syncAllPublishedDirectSaleToPos (toléré)
5. prices → rebuildPOSPriceIndex (toléré)
6. Parallèle : detectCatalogDuplicates + detectPricingDrift + recalculateCategoryCounters
7. getPosCatalogue('commercial') + notify + audit log
8. Retourne ok:true même si erreurs secondaires absorbées
Analyse critique : deux orchestrations distinctes coexistent. sync-pos est fail-fast global ; syncAll est tolérant/partiel. Risque : l’UI peut afficher « Synchronisé » alors que options/index/drift ont échoué silencieusement.
