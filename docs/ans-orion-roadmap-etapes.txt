1. REGLE ABSOLUE : ZERO SUPPRESSION
============================================================

REGLE PRINCIPALE :
Ne jamais supprimer une fonctionnalité existante, un module, une route, un composant, une donnée, un menu, un sous-menu, une logique, une page, une carte, un tableau ou une option déjà présente.

Le but est :
- améliorer ce qui existe,
- corriger ce qui est cassé,
- compléter ce qui est incomplet,
- rendre fonctionnel ce qui est décoratif,
- réorganiser ce qui est mal placé,
- uniformiser ce qui est incohérent,
- ajouter ce qui manque,
- connecter les modules entre eux.

Si un élément semble parasite :
1. ne pas le supprimer directement ;
2. analyser son rôle ;
3. le corriger si possible ;
4. le déplacer si nécessaire ;
5. le renommer si nécessaire ;
6. le rendre fonctionnel ;
7. si vraiment inutilisable, le masquer avec commentaire clair dans le code ;
8. conserver une trace de la raison.

Interdictions :
- ne pas supprimer de route ;
- ne pas supprimer de composant ;
- ne pas supprimer de module ;
- ne pas supprimer de page ;
- ne pas supprimer de logique métier ;
- ne pas supprimer de donnée de test utile ;
- ne pas refaire l’application à zéro ;
- ne pas casser l’existant ;
- ne pas remplacer un module fonctionnel par une maquette moins complète ;
- ne pas changer les noms de routes sans nécessité forte ;
- ne pas supprimer un bouton : lui donner une action réelle ;
- ne pas supprimer une option POS : la corriger, la classer, la renommer ou l’améliorer.

Règle de laize :
- calculer automatiquement la meilleure laize ;
- appliquer la marge de sécurité si nécessaire ;

- si un côté correspond exactement à la laize disponible, ne pas appliquer inutilement la marge ;
- afficher la surface réelle et la surface facturée ;
- expliquer visuellement le calcul.

Exemple attendu :
- Dimension réelle : 115 x 300 cm
- Surface réelle : 3,45 m²
- Laize utilisée : 120 cm
- Surface facturée : selon règle de laize
- Prix total : calculé automatiquement.
