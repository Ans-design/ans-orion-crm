Deux couches « next action » existent : lib/flow/next-action.ts (générique) et lib/commande/order-next-action.ts (hub). Risque mineur de messages divergents si fallback générique. Recommandation : hub commande = seule source pour entity: 'commande'.

  • ~47 fichiers AUDIT_*.md à la racine + nombreux scripts / logs → signal/bruit.
  • docs/SECURITY.md trop court (~25 L) face à la surface réelle.
  • Action : index docs/README.md ; archiver audits hors chemin opérationnel.

5. Sécurité & accès

Positif : middleware JWT large, rate-limit auth, headers sécurité, CSP Report-Only, redirects non-autorisés, BAT client tokenisé, cron derrière CRON_SECRET.
  • Public API : /api/auth, /api/bat/client, /api/setup-db, /api/auth/setup-status.
  • Pages sensibles protégées partiellement : /administration, /rh/paie, finance…
  • Gaps page-access : plusieurs écrans RH et ops accessibles à tout utilisateur connecté si la page existe.
  • Signup / demo : vérifier DEMO_MODE, ALLOW_PUBLIC_SIGNUP, ALLOW_SETUP_DB en prod Hostinger.
  • ZIP précédent : l’archive « ANS PROJET PRES FINAL TEST 50 » peut contenir des .env* — traiter comme compromis potentiel et rotator.

9. Design system & UX

  • Canon : rouge #cc0033, vif #ff1e56, jaune #eab308, radius 7px, Soft UI.
  • Écarts : présence de rounded-full / rounded-xl hors design system ; gradients ponctuels (ex. anciens boutons Admin).
  • Triple CSS Admin (admin / administration / backoffice-v2) → styles et patterns divergents.
  • UX récente positive : menu compte dans sidebar (plus de doublon header) ; Temps & capacités pleine largeur 2 colonnes.
  • Accessibilité : labels / focus-ring partiels ; à renforcer sur formulaires POS et modales Admin.
  • États vides / erreur : encore hétérogènes (certains catch silencieux = vide trompeur).
